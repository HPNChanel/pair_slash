## Objective

Upgrade the MCP config emitters (`mcp/servers.yaml` sidecars, config fragments) so generated MCP wiring is aware of the 2026-07-28 spec era — emitting era-appropriate structure and guidance instead of legacy-only assumptions.

## Context & sources

- 2026-07-28 changes that matter to emitters: stateless core (no `initialize` handshake reliance), `Mcp-Method`/`Mcp-Name` required HTTP headers, per-request `_meta` (`io.modelcontextprotocol/protocolVersion` etc.), `server/discover` RPC, OAuth/OIDC-aligned auth, formal deprecation.
- Emitters: search compilers for `mcp` emission — `compileCodexPack emits MCP config`, `compileCopilotPack emits MCP sidecars` (existing tests reference these). Runtime-mapping doc lists `mcp/servers.yaml` + `mcp/<file>`.
- Consumes `spec_era` field from T2-04.
- Both runtimes' native MCP config formats differ (Codex `config.toml`/`mcp` surfaces vs Copilot `.mcp.json`) — emitters must produce runtime-native shape with era-aware content.

## Files to touch

- `packages/runtimes/codex/compiler/src/` — MCP config emission
- `packages/runtimes/copilot/compiler/src/` — MCP sidecar emission
- `tests/golden/` — updated MCP emit goldens
- `docs/runtime-mapping/*.md` — surface mapping rows for `mcp` if shape changed (T1-03 already refreshed — coordinate)
- Do NOT touch: manifest schema (done in T2-04), pack sources (unless their declared MCP deps need era values — handle in T2-04's manifest pass)

## Work steps

1. Locate MCP emission in both compilers (`grep mcp` under compiler srcs).
2. For each runtime, emit era-aware output:
   - Copilot: `.mcp.json` shape with era annotation (e.g., per-server `spec_era` or comment-doc + generated `pairslash-mcp.json` manifest describing era expectations).
   - Codex: config fragment w/ era notes; document header requirements for streamable HTTP servers.
3. Include guidance blocks in emitted docs: `server/discover` availability, `UnsupportedProtocolVersionError` handling expectation, auth-era notes.
4. Goldens updated; test: pack with `spec_era: modern` emits modern-era sidecar; `legacy` emits legacy-shaped + deprecation note; `dual` emits both notes.
5. Gates: compiler tests, lint, test, typecheck.

## Constraints (STRICT)

- MUST NOT emit runtime config that assumes session-scoped MCP (initialize handshake) when `spec_era: modern` — era mismatch is a lint-visible condition.
- MUST keep emitted MCP artifacts declarative — PairSlash config files describe servers; runtimes own connection management.
- MUST NOT auto-register servers into runtime global config without preview (C.4) — emission is into the pack's own files; installer surfaces them.
- MUST keep emitted files deterministic (sorted servers, stable formatting).
- MUST NOT claim runtime MCP support levels beyond lane evidence — emitted docs use "expected"/"requires" wording, not "verified".
